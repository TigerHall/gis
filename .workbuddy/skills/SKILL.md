# Update Changelog

## Overview

专门的 OGV 项目更新记录技能。每次完成实质性修改后自动提炼变更要点、写入工作记忆、更新 CHANGELOG。

当用户明确要求"把修改写进记忆"、"更新 CHANGELOG"、"整理今天的修改"时触发。也可在完成大型修改（8+ 次工具调用、或涉及多个文件的关键修复/重构）后主动调用。

## Workflow

### Step 1: 提取变更要点

回顾当前会话中所有修改，按以下维度组织：

- **文件变更清单** — 修改/新建/删除的文件路径
- **功能改动** — 每个改动的目的和实现方式
- **关键决策** — 为什么选择这个方案、放弃了哪些方案
- **已知问题 / 后续** — 遗留问题或未来优化方向
- **CSS 类名 / 选择器变更** — 如果涉及重命名，记录新旧映射

### Step 2: 写入工作记忆

按以下规则写入：

1. **日级日志** `.workbuddy/memory/YYYY-MM-DD.md`
   - 存在则 append，不存在则先创建目录和文件
   - 用 `##` 二级标题分隔每个独立改动
   - 按时间倒序排列（最新在最上面）

2. **长期记忆** `.workbuddy/memory/MEMORY.md`
   - 只记录跨会话有用的持久性知识（架构决策、命名约定、关键修复）
   - 不记录临时搜索、路径、工具报错

3. **用户偏好** `~/.workbuddy/MEMORY.md`
   - 跨项目的用户偏好才写到这里

### Step 3: 更新 CHANGELOG

文件路径：`docs/CHANGELOG.md`

格式要求：

```markdown
## YYYY-MM-DD

### 改分类标题

- 使用列表描述每个改动
- 关键技术细节放在括号内
- 涉及重命名的写清楚新旧对照

---
```

- 先检查当天是否已有 section，有则追加，没有则新建（插到文件最顶部、上一个版本的 section 之后）
- 分类标题用 `###` 三级标题，如 `### 侧边栏布局重构`、`### Bug 修复`
- 每条改动用 `- ` 列表，关键文件路径、类名、函数名用反引号包裹
- 条理清晰，每条一个独立改动点

### Step 4: 清理示例文件

删除 `scripts/`、`references/`、`assets/` 下的示例文件（本技能不需要 bundled resources）。
