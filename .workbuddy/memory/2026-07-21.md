# 2026-07-21

## PWA 版号显示 & 更新刷新逻辑修复

### 现象
- `appVersion` div 在旧代码里由 `app.js` 启动期 `fetch('service-worker.js?Date.now()')` 抠 `CACHE_NAME` 写入 → 显示的其实是「将来才生效的新版本」，而非正在运行的版本（用户报「直接显示还没载入的版号」）。
- 弹窗「刷新」按钮 `onAction` 里 `postMessage(skipWaiting)` 后立即 `location.reload()`，reload 抢在新 SW `activate`/`clients.claim` 完成之前 → 仍由旧 SW 服务、从旧缓存吐旧 `geojsonloader.js`，刷新像没用。
- SW `fetch` 用 `caches.match()`（默认搜全部缓存），与 `activate` 删旧缓存存在竞态，可能从旧缓存命中过期资源。

### 修复（已落地）
- `assets/app.js`：
  - 删除启动期写 div 的 fetch；改为页面在 `load` 且 `navigator.serviceWorker.controller` 存在时，向 controlling SW 发 `{type:'GET_VERSION'}`，SW 回 `{type:'SW_VERSION', version:CACHE_NAME}`，`setAppVersion` 写入 div → div 永远等于「当前控制页面的 SW 版本」。
  - 弹窗 `onAction` 只置 `_needsReload=true` 并 `postMessage(skipWaiting)`；真正 reload 放到 `controllerchange` 监听里，确保新 SW 已接管页面再 reload（避免首次访问 controllerchange 误 reload）。
- `service-worker.js`：
  - `message` 监听新增 `GET_VERSION` 分支，回传 `CACHE_NAME`。
  - `fetch` 由 `caches.match(req)`（全缓存）改为 `caches.open(CACHE_NAME).then(cache=>cache.match(req))`，限定当前版本缓存，杜绝跨版本命中旧 `geojsonloader.js` 等。

### 行为验证要点（逻辑推导，未跑真机）
更新流程：后台新 SW `installed` → 弹窗 → 点刷新 → `skipWaiting` → 新 SW `activate`(删旧缓存)→`clients.claim`→`controllerchange`→(`_needsReload`)reload → 新 SW 控制 → `load` 时 `GET_VERSION` → div 显示新版本。首次访问：`controller` 初始为 null，`controllerchange`(claim) 后请求版本，无 reload。已 `node --check` 通过。
