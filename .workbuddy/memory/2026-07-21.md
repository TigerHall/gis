## web+dupal 协议注册坑 — manifest 不自动注册，需运行时+用户手势

- **根因**：`manifest.json` 的 `protocol_handlers` 在 **Chrome/Edge 稳定版不会自动注册**自定义协议（Chromium 该字段默认不生效，需 flag）。用户实测地址栏/Win+R 输入 `web+dupal://focus/南海` 提示"没有打开此链接的应用"——系统注册表根本没该 scheme。
- **正确做法（已实施）**：运行时 `navigator.registerProtocolHandler('web+dupal', location.origin+'/?proto=%s', 'Dupal地图')` 必须在**用户手势（点击开关）栈内**调用，否则被浏览器拒绝。
  - 已做成「⚙️ 地图设置 → 高级」开关 **「链接跳转🧪」**（TOGGLE_GROUPS 渲染 + toggleConfig.linkJumpToggle.enable 行为，由 initToggle 自动绑 change）。开启即注册；handler 用 `location.origin` 动态拼接，避免硬编码域名在 localhost 下报 "document's origin" 错误（用户实测踩坑）。移除早期那枚独立按钮方案。
  - `manifest.json` 的 `protocol_handlers` 字段**保留**作 Firefox 等补充（FF 安装 PWA 时可能自动注册），但 Chrome/Edge 不依赖它。
- **行为预期**：用户点「启用」后，`web+dupal` 写入系统 → 地址栏/网页链接/Win+R 均可调起并聚焦；Firefox 注册的协议不写系统注册表，仅浏览器内点击生效、Win+R 用不了；Safari/iOS 基本不支持。地址栏输入打开的是 dupal.cn 普通标签页（聚焦仍生效），不一定拉起独立 PWA 窗口。
- 设计文档 `docs/keyword-jump-design.md` §4 已修正错误结论（原"manifest 安装即自动注册"改为"运行时+用户手势"）。

## 修复：图层放大镜(🔍)缩放边界不对 — computeBounds 漏算 MultiPolygon 子面

- **现象**：点图层放大镜按钮，多边形图层只缩到极小区域，不是整个矢量边界。以「浙江适飞区(2026-05-12)」为例：1 个 Feature、几何类型 MultiPolygon、**内含 1336 个子多边形**（浙江各地分散空域）。
- **根因**：`assets/geo-utils.js` 的 `computeBounds`（约 345 行）多边形分支对 MultiPolygon 只取 `c[0]`（第一个子多边形），其余全忽略。`flyToLayer`(geojsonloader.js:1676) 用的 `layerBoundsCache` 正是由 `computeBounds` 算出 → 放大镜只框住第 1 个小空域。
- **量化验证**（真实数据）：旧逻辑 bounds=lat 28.58~28.77 / lng 119.76~120.05（一个~20km 小空域）；新逻辑=lat 27.16~31.18 / lng 118.02~122.59（与真实浙江吻合）。
- **修复**：多边形分支改为 `polygons = type==="polygon" ? [c] : c`，遍历全部子多边形+全部环，并对坐标做 `[lng,lat]` 数值校验。点/线分支原逻辑本就遍历完整，无此 bug。
- **影响范围**：所有 MultiPolygon 图层（省界/国界/海域/勘探区等）放大镜此前均只框首个子面，现统一修好。`flyToLayer` 与 `loadGeoJSONLayer` 的 `layerBoundsCache` 均受益；初始加载 fitBounds 走 `baseGeoJson.getBounds()`(Leaflet 原生，本来就正确)。`node --check` 两文件通过。

## 优化搜索隔离方案两次迭代（重要决策记录）

- **V1 要素级 B 方案（已废弃）**：原用半透明+临时单要素层（`_isoState`/`isolateFeature`/`restoreIsolation`），并给 `applyLayerOpacity` 补了 Canvas 分支。→ 实测出现「搜索后图层不受侧边栏开关控制、显示后关不掉」的副作用（临时层/半透明对象绕过了标准 load/remove 路径）。**已废弃**：用户 revert 了 geojsonloader.js，改用 V2。
- **V2 复用侧边栏开关 + 临时单要素层（最终采用，2026-07-21 用户二次修正）**：完全走标准开关路径，从根上消除「关不掉」。
  - **用户最终要求**：点结果→关掉【所有】图层（**含被搜索的目标图层**），新建一个只含该要素的临时 `L.geoJSON` 显示目标；用户移动/缩放→**销毁**临时层 + 恢复隔离前已勾选的所有图层（被搜索层若隔离前未勾选则不恢复）。
  - `_setLayerChecked(cbId,on)`：`document.getElementById(cbId).checked=on` 后 `dispatchEvent(new Event("change"))` → 复用各图层既有 change 处理器（内置层走 loadGeoJSONLayer/removeGeoJSONLayer，用户层走 map.add/removeLayer）。已是目标状态则跳过，避免重复 load/remove。
  - `_allLayerCheckboxes()`：选择器 `#dataLayerContent .layer-item input[type=checkbox], #userLayerGroup .layer-item input[type=checkbox]`（只图层项、不碰分组「全选」复选框）。
  - `_isolateToLayer(cbId,feat)`：① 已隔离则先 `_restoreFromSearch()`；② 记录隔离前所有 `checked` 图层 cbId → `_isoRestoreSet`；③ **`_allLayerCheckboxes()` 全部 `_setLayerChecked(id,false)`（含目标层）**；④ 用 `feat.geometry` + `layerColorMap[cbId]` 颜色新建临时 `L.geoJSON`（点用 circleMarker）`.addTo(map)`，存 `_isoTempLayer`；⑤ `map.once("moveend",()=>map.once("movestart",_onUserMapInteract))` 等定位动画结束再绑恢复、`setTimeout(700)` 兜底。
  - `_destroyTempLayer()`：`map.removeLayer(_isoTempLayer)` 并置 null。
  - `_restoreFromSearch()`：**先 `_destroyTempLayer()`**，再把 `_isoRestoreSet` 全部 `_setLayerChecked(id,true)`，清状态、`map.off("movestart",_onUserMapInteract)`。暴露为 `window.__OGV_restoreIsolation`。
  - `_isOptSearchOn()`：读 `window.OGV_OPT_SEARCH.enabled`，无则回退读 `#optimizeSearchToggle` 的 `checked`。
  - 接入：`highlightAndLocateFeature(cbId,feat)` 顶部 `if(_isOptSearchOn()) _isolateToLayer(cbId,feat);`（注意传 feat 用于建临时层）。
  - **行为**：点结果→所有层关闭、仅临时层显示被点要素（坐标定位）；用户移动/缩放→销毁临时层 + 原开图层全部勾回（被搜索层若之前没开则保持关）；连续点结果→先恢复再隔离新目标；关开关→立即恢复。无半透明对象、侧边栏始终反映真实状态。
- **改动文件**：`assets/geojsonloader.js`（仅此文件重写隔离逻辑；V1 补的 `applyLayerOpacity` Canvas 分支随 revert 已移除，无需保留）。`assets/app.js` 的 `optimizeSearchToggle` 配置天然兼容（仍引用 `window.__OGV_restoreIsolation`）。`node --check` 两文件通过。
