## 修复 fixRingCoords 跨180°多边形渲染 Bug

**问题描述**：
`plate16_Featur_FeaturesToJSO.json` 中的北太平洋板块（id=48）跨越180°子午线，在地图上：
1. 50°N以北的北极区部分被切割不显示
2. 三个世界副本中50°N以北都没有显示
3. 最右边多出一块异常图形

**根本原因**（`assets/geojsonloader.js`）：
旧 `fixRingCoords` 使用 `while (dLng > 180) cur[0] -= 360` 的"折叠"策略。
对于起点在+179.998°的多边形，经过北极区跳到-179.991°时，dLng ≈ -360，
算法把第3点从 -179.991 修正为 +180.009（正确），但随后后续所有"西半球"负经度点
被累积加 360，导致坐标全堆积在 [180, 360] 区间，在世界副本体系中错位到最右侧，
50°N以北看不到，在最右边出现异常片段。

**修复方案**：
改用"展开"策略：第一个点规范化到 (-180, 180]，后续每个点计算与前点的最短路径跳变
（将 dLng 规范化到 (-180, 180] 区间，允许 cur[0] 超出 ±180）。
展开后坐标可超过 ±180，Leaflet 正确处理为世界副本坐标。
offset=-360 副本将展开的 [180,360] 坐标移回 [-180,0] 区间，正确显示西半球板块。

**修改文件**：
- `c:/Users/hehu/Documents/GitHub/gis/assets/geojsonloader.js`：
  - 重写 `fixRingCoords()`，改为展开策略
  - 新增辅助函数 `ringCrossesAntimeridian()`（备用）
  - `fixGeometryCoords` 和 `fixAntimeridian` 逻辑不变

## 修复多边形拓扑反向（渲染"补集"）Bug

**问题描述**：
上述跨180°多边形（北太平洋板块 id=48）能显示出来了，但渲染为"反向"——
50°N以南被填充，50°N以北反而是空的，看起来是整个地球除该板块以外的区域被填充。

**根本原因**：
该要素的 GeoJSON 坐标序列是**顺时针**方向，违反了 GeoJSON RFC 7946 规定的外环逆时针（右手定则）。
Leaflet 遵循右手定则，顺时针外环被解释为"孔洞"而非填充区域，
导致整个地图（世界）被填充而该多边形内部为空。

**验证**：
Shoelace 有符号面积公式：该多边形 signedArea < 0 → 顺时针 → 需反转。
反转后 signedArea > 0 → 逆时针 → 正确渲染板块本身区域。

**修复方案**（`assets/geojsonloader.js`）：
- 新增 `ringSignedArea(coords)`：Shoelace 公式计算有符号面积
- 新增 `fixRingWinding(rings)`：对 Polygon/MultiPolygon 的每个环检测绕向，
  外环顺时针则反转，内环逆时针则反转
- `fixGeometryCoords` 对 Polygon/MultiPolygon 在 `fixRingCoords` 之后调用 `fixRingWinding`
- 删除了此前无实际用途的 `ringCrossesAntimeridian` 辅助函数

## 新增交互与可视化功能（2026-04-25 晚）

**1. 单击/双击解耦**（`geojsonloader.js` `onEachFeature`）：

- `click`：仅显示信息弹窗（所有要素类型）

- 不再使用 `L.circleMarker`（不可控描边）

**3. 站点图层自动标签**（IODP/ODP/DSDP）：
- 配置 `STATION_LABEL_CONFIG`：DSDP(Hole)、ODP(Fullname)、IODP03-13(Name)、IODP13-26(site)
- `buildStationLabelLayer()`：为每个站点创建文字标签层
- `map.on('zoomend')`：zoom ≥ 5 时自动显示标签，< 5 隐藏
- 标签样式：白色半透明背景 + 绿色描边小字

**修改文件**：
- `assets/geojsonloader.js`：图标工厂函数、click/dblclick 解耦、站点标签系统
- `assets/main.css`：`.station-label` 样式

**背景**：
ArcGIS Pro 导出的 GeoJSON（PJSON 格式）外环使用**顺时针**方向，与 GeoJSON RFC 7946 逆时针规范相反，这是 ESRI 的惯例而非数据错误。`fixRingWinding` 已处理此问题。

**新增 rewindRingStart 优化**：
将多边形环的起始点旋转到经度绝对值最小（最远离±180°）的点，让 `fixRingCoords` 展开算法从最稳定的位置出发，避免起点在±180°附近产生的边界歧义。

**最终三层处理链（Polygon/MultiPolygon）**：
① `rewindRingStart` → 起始点旋转到远离±180°
② `fixRingCoords` → 展开消除跳变（允许坐标超出±180°）
③ `fixRingWinding` → 修正 ESRI 顺时针→逆时针（右手定则）
