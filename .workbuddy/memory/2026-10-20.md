  520~760px 另加 `min(520px, 62vh)`。390×780 实测 430px / 55%（原 562px / 72%）。
- 窄屏收紧 `.ogv-ai-head` / `.ogv-ai-comp` / `.ogv-ai-msgs` 内边距（输入区加 `env(safe-area-inset-bottom)`）。
- 新增「点地图自动收起」：`close(opts)` 支持 `keepRequest`；`_bindMapAutoCollapse()` 在 `_boot()` 与每次

  `(max-width:760px), (max-height:520px)`，宽屏不触发。**关键决定：不 abort 在途请求**

### 2 点集转线 / 转面（`pointdrop.js` 折叠区 `details.pd-conv`）

- 分组字段（`<select multiple size=3>`，按组合值分区）+ 排序字段（首项 `""` = `# 表格行序`）
  + 降序 + 闭合线 + 两个按钮「➡ 转线 / △ 转面」。
- 一次只 `addUserLayer` 一个 FeatureCollection，内部多条 LineString / 多个 Polygon。
- 线 ≥2 点、面 ≥3 点，不足的分组跳过并计数（toast 里报）。面自动补首点；线按勾选补。
- 属性：分组字段原样 + `Name`（用组值当标签）+ `点数`；线加 `长度_km`（haversine），
  面加 `面积_km²`（与 index.html `calculatePolygonArea` 同一球面公式，单位换成 km）。
- 排序：数字字段按数值、其它按 `localeCompare(...,{numeric:true})`。
- `generateLayer()` 顺手改用 `collectValidRows()`，与转线转面共用一套「有效行」判据。

### 3 顺手修掉的既有 Bug（单测发现）

`onPasteInput` 把解析结果提示**回写进同一个 textarea**，而它挂在 `input` 上 →
用户接着敲一个字就拿提示文字再解析一遍：数据行切不出（长度不足被 `continue`），
但 `pointDropCols` 已在前面被赋成 `[]` → **数据还在、字段（列）全丢**，
连带所有额外字段值丢失（症状：分组选了 `line` 却全归一组、Name 变成「(空)」）。
修法：先把数据行切成 `rawRows`，**确认非空再动 `pointDropCols`**；空则直接 return。
→ 已提炼成规则写进 MEMORY.md §12。
