## 搜索分词正则统一修复
- **问题**：`DJI_20250629114919_0003_Z.JPG` 等含下划线/点号的字段值无法搜索到
- **根因**：索引构建用 `/[^a-z0-9\u4e00-\u9fff]+/` 分词（下划线是分隔符），但查询侧用 `/\s+/`（仅空格分隔），用户输入 `DJI_20250629114919_0003_Z.JPG` 被当作一个整体 token，匹配不到
- **修复**：`runSearch` 中查询分词正则从 `/\s+/` 改为 `/[^a-z0-9\u4e00-\u9fff]+/`，与索引构建一致
- 效果：输入含下划线、点号的字符串也能正确搜索到（会被拆分为多个词取交集匹配）

## 搜索模糊匹配
- **问题**：`202506` 无法匹配到 `20250629114919`（精确 token 匹配）
- **修复**：`runSearch` 中每个查询 token 先尝试精确匹配，无结果时遍历索引 keys 做子串匹配（`indexOf`），用 Set 去重合并命中结果
- 多词仍然取交集；精确匹配优先（O(1)），子串匹配兜底（O(keys)）
- 效果：输入 `202506` 能匹配到含 `20250629114919` 的 feature

## 搜索结果点击跳转报错修复
- **问题**：Canvas 大数据集点击搜索结果报 `gl.eachLayer is not a function`，关图层再开就好了
- **根因**：`highlightState[cbId].geoLayers` 对 Canvas 图层也存在，但 Canvas 图层（`L.markersCanvas`）没有 `eachLayer` 方法，代码错误走了 DOM 分支
- **修复**：点击前检查 `geoLayers` 中是否有 `setFeatures` 方法的图层（Canvas 标志），有则跳过 `eachLayer` 分支走 Canvas 坐标定位分支

## 搜索索引 IDB 缓存（V2 修复）
- **V1 问题**：用 `checkboxId`（如 `layer_0`）做缓存 key，图层顺序变化或文件内容更新后缓存错位
- **修复**：缓存 key 改为 `fileName`（文件名唯一标识图层）；存 `featureCount` 做版本检测，feature 数量变化自动重建
- **用户上传图层**：`buildSearchIndex(uid, features, null)` 第三个参数 `cacheKey=null` 时不走 IDB 缓存，避免用户文件污染内置图层缓存
- `buildSearchIndex(checkboxId, features, cacheKey, callback)` — cacheKey 为 null 时直接构建（不缓存），非 null 时先查 IDB
- **push 报错修复**：提取 `tokenizeFeatures()` 公共函数，缓存命中时校验 `typeof cached.tokens === "object" && !Array.isArray(cached.tokens)`，格式异常直接重建
- **push 报错根因**：`tokens = {}` 有原型链，PBDB 数据中某个 feature 的 properties 包含 `"constructor"` 字符串，分词后 `tokens["constructor"]` 命中 `Object.prototype.constructor`（函数），`push` 报错。改用 `Object.create(null)` 创建无原型对象彻底解决
- **NaN 大小修复**：`setCache` 日志引用 `record.size` 但新缓存不存 size 字段，需删掉 `formatBytes(record.size)`
