## 修复 Gazetteer 图层不显示（N 点/线/面）计数后缀
- 现象：4 个 Gazetteer 图层勾选加载后，图层名后面没有 `(N 点/线/面)` 计数，而其他图层有。
- 根因：`updateLayerCount` 原本放在 `if (!searchIndexMap[checkboxId])` 分支内（loadGeoJSONLayer 第 1155 行）。Gazetteer 带 `searchPriority:true`，启动 2s 后台建索引已设置 `searchIndexMap`，致使勾选加载时该 if 为 false、整段跳过，计数不渲染。
- 修复：把 `updateLayerCount` 抽出为「图层加载完成即无条件执行」（函数内部有空 features 保护），并删除分支内冗余的重复调用。已 `node --check` 通过。

## 搜索结果点击不跳转 + 结果数过少（geojsonloader.js / main.css）
- 现象1：点击要素搜索结果不跳转定位。根因：`highlightAndLocateFeature` 非 Canvas 分支只靠 `layer.feature._featureIndex === feat._featureIndex` 跨对象匹配；但搜索结果的 `feat` 来自 `featureCache`，对 `searchPriority` 图层（initPrioritySearchIndices 用原始 fetch 填充、未渲染，`_featureIndex` 未赋值）及「点击后加载」的要素，`feat._featureIndex` 为 undefined → 匹配失败→不跳转。矢量化的 Gazetteer 图层（multilinestring 1184、multipolygon 1663 均≤3000点→DOM矢量）中招；Canvas 的 point 反而正常。
- 修复1：重写 `highlightAndLocateFeature`，**始终基于 `feat.geometry` 真实坐标定位**（任意图层/加载状态都可靠），`_featureIndex` 仅作为找到已渲染矢量要素时的「高亮+弹窗」增强；找不到则退回坐标定位。复用既有 `extractCoords`（返回 [lat,lng]）。
- 现象2：结果底部"30 条太少"，且无"查看更多"按钮（原只是静态提示）。
- 修复2：新增 `FEATURE_SEARCH_CAP=200`（每图层每阶段上限，原 30，matchLayerFeatures 与 Phase2 均改用）、`SEARCH_PAGE=50` 初始、`SEARCH_PAGE_STEP=50`；`renderResults` 加分页缓存 + 可点击「查看更多（还剩 N 条）」按钮（基于实际 results 长度分页），全部展示完且底层仍有更多时显示提示。`main.css` 新增 `.search-loadmore` 样式。已 `node --check` 通过。
