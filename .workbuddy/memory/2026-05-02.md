## 修复用户上传图层 🎨 按钮报错（2026-05-02 续）
- 根因：`openColorModal(uid, fileName, null)` 传入 `null` 作为 filePath，导致 `fetchGeoJSON(null)` → IndexedDB 报错；且 `addUserLayer` 向 `highlightState[uid]` 写入了错误形状的对象（只有 `geoJsonData/fileName`，缺少 `geoLayers`），导致 `clearHighlight` 访问 `state.geoLayers` 时报 undefined
- 修复：`addUserLayer` 改用独立变量 `userLayerGeoJson[uid]` 存储 `{ geoJsonData, fileName }`，不再污染 `highlightState`
- `openColorModal`：filePath 为空时从 `userLayerGeoJson[checkboxId]` 读取数据，不再调用 `fetchGeoJSON(null)`
- `reloadLayerWithNewMode`：`savedData` 从 `userLayerGeoJson[checkboxId]` 读取；重建用户图层后不再错误写回 `highlightState`
- `clearHighlight`/`applyHighlight`：增加 `!state.geoLayers` 守卫，防止访问未定义属性
- Service Worker 版本号更新至 `v1.4.2`

## 修复全选/取消全选后用户图层报错（2026-05-02 续）
- 根因：`addUserLayer` 创建的 checkbox 没有设 `value` 属性，浏览器默认值为 `"on"`，`selectAllLayers` 无差别地对所有 checkbox 调用 `loadGeoJSONLayer(cb.value, ...)` → 发起 `fetchGeoJSON("on")` → 404
- 修复：用户图层 checkbox 加 `dataset.userLayer = "true"` 标记，`selectAllLayers` 跳过用户图层并直接用 `layerCache[id].addTo(map)`；`rebuildLoadedPointLayers` 同样跳过用户图层
- checkbox change 事件：`map.removeLayer(layerCache[uid])` 加 null 检查
- Service Worker 版本号更新至 `v1.4.4`
