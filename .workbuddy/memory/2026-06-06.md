# 2026-06-06

## Shapefile 中文乱码问题 — 最终总结

### 结论
**本次问题主要是数据问题，不是前端问题。**

### 关键发现
1. `shp.min.js` 读取 `.cpg` 文件后，用 `TextDecoder` 解码
2. 浏览器 `TextDecoder` 不支持 `GB2312`，只支持 `GBK`
3. 但 `shp.min.js` 没有做 `GB2312` → `GBK` 的映射
4. 所以 `.cpg` 存在但内容为 `GB2312` 时 → 解码失败 → 回退 UTF-8 → 乱码

### 尝试过的方案（效果均不理想）
- **方案 1**：修改 `shp.js`（未压缩版）→ 无效，实际运行 `shp.min.js`
- **方案 2**：`geojsonloader.js` 中注入 `.cpg` 文件 → 不靠谱，无法可靠判断编码
- **方案 3**：`handleFolderUpload` 中对每个 .shp 重新打包配套文件 → 本应有效但实际测试不生效
- **方案 4**：`index.html` 中 zip 上传逻辑对齐文件夹上传 → 未测试

### 判断
- 前端不适合处理编码检测/修正问题
- 单个 `.shp` 压缩成 `.zip` 上传时，`shp(buffer)` 自己解压找配套文件，逻辑是完备的
- 如果 `.cpg` 内容是 `GB2312`，这是数据源的问题，应该在数据端解决
- 最好的处理方式：**如果已知中文乱码，用文本编辑器将 `.cpg` 文件内容改为 `GBK` 或 `UTF-8`**

### 后续建议
- 前端可以保留 `companionExts` 扩展到 8 个文件的改动（无害）
- 前端可以保留对 `.cpg` 缺失/内容为 `GB2312` 的警告提示（有用）
- 但不要指望前端能完美解决编码问题
- 需要改的是 `shp.min.js` 的 `createDecoder`（如果允许修改第三方库的话）
