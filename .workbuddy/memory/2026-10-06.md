## 出图重做：论文级出图 + 悬浮中台（v3.2.0 → v3.3.0）

### ⚠️ 最重要的一条：**「底图瓦片不对」不是 CORS**

我一开始（和用户）都判断是跨域污染 canvas。**实测 31 个底图逐个验证后推翻了**：

| 检测 | 结果 |
|---|---|
| 会污染 canvas 的底图 | **0 个** |
| crossOrigin 覆盖 | tianditu/arcgis/wms/tile 四种 kind 全带（`basemap-manager.js:105/115/139/147`） |

**真凶 = 没等瓦片加载完就截图**。旧 `app.js:957-958` 只 `requestAnimationFrame` 两帧，
WMS 底图单瓦片要几百 ms~数秒。同一底图两种时机对比（决定性证据）：

| 时机 | 导出图颜色数 |
|---|---|
| 立刻导出（旧行为） | **11 色**（≈纯色，瓦片全丢） |
| 等瓦片 load + decode 完 | **2863 色**（正常） |

**为什么长期没暴露**：ArcGIS/天地图走缓存命中看着正常，一换 WMS 就大面积丢瓦片。

### 新引擎（`assets/map-export.js` + `map-export-ui.js` + `map-export.css`）

### 踩到的坑（都是实测撞出来的）

1. **认底图不能只读配置名、也不能取「第一个 TileLayer」** ——
   `map.eachLayer` 会拿到**覆盖层**（天地图世界境界 `ibo_w`）。实测 ArcGIS-海洋 下

5. **图例与图标题重叠** → `drawTitle` 改成返回占用高度，图例据此下移。
6. **dpi 公式方向反了**：`dpi = 0.0254/mpp` 其实是「每英寸多少米」，z5 下算出 `0 dpi`、949 万 mm。

7. **新 UI 别用 `--c-text-dim`**（#999 浅 2.85:1 / #777 深 4.22:1，未达 AA）→ 用 `--c-text-alt`。

## v3.3.1 修出图两个真 bug（用户实测报出）

### ① 导出图里没有矢量要素 —— 面要素全丢

**`L.Polygon` 继承自 `L.Polyline`**（Leaflet 1.9.x）——
所以 `layer instanceof L.Path && !(layer instanceof L.Polyline)` 这个「挑出面」的写法
**永远为假**，所有面都掉进线分支、只描边不填充 → 看起来就是「导出图没有面」。
**判面必须先判 `L.Polygon` / `L.Rectangle`。**

同批修掉三处：
- **线要素带透明点击热区**（`geojsonloader.js:1273`，`opacity:0` + `_isHitLayer:true`）
  —— 不排除会数出双倍要素 + 画出看不见的粗线。实测 176 条。
- **`getLatLngs()` 嵌套层数不能按固定值判**：`1全球洋壳` 长度 48、`ll[0]` 是**长度 1 的数组**
  （MultiPolygon 被套一层）→ 按「`ll[0][0]` 有没有 lat」判层级会误判成空环，面还是画不出。
  改成**递归摊平到「叶子是 latlng 序列」为止**。
- **内环没挖空**：每环各自 `fill()` → 内环被当独立面再填一遍。
  改成所有环进**同一 path** 再 `fill("evenodd")`。
  为此 `tracePath()` 不再自己 `beginPath()`，调用方决定。

### ② 换底图 `Cannot read properties of undefined (reading 'length')`

`drawXYZ()` 要 `desc.subdomains.length` 算 `{s}`，而**只有 `describeBasemap()` 设了这个字段，
`describeOverlays()` 漏了**。天地图世界境界 `ibo_w` / 地名标注 `cva_w` 正是走覆盖层这条路。
→ `describeOverlays()` 补 `subdomains`；`drawXYZ()` 开头兜底 `if (!desc || !desc.url)`。
教训：**底图与覆盖层共用 `drawXYZ`，任一侧漏字段都会炸整张图，兜底要加在共用函数里。**

### ③ 顺带：线宽缩放系数原来错的
`scaleFactor = W/1400` 估算 → 图幅一改宽线宽就跟着变。应为
`scaleFactor = 2^(出图zoom - 地图当前zoom)`（每高一级屏幕像素宽翻倍）。
UI 预览里写死的 `scaleFactor: 420/1400` 要去掉，否则预览与大图粗细不符。

### 回归（跨几何类型，白底看是否真有像素）
面(多环/带洞) ✅✅✅✅ ｜线 ✅✅✅ ｜点 ✅✅✅（洋壳1/大洋域4/洋中脊域71/陆块167/
MOR&TF 176/海沟101/AtlFz 103/火山227/热点98/热液口146）。
⚠️ `Atlantic_FZ`/`hotspots` 首测 0 像素是**测试视野没罩到数据**（前者只分布南大西洋
lng -21~6）—— 移到实际位置即正常。**测出图必须先确认数据在视野内，否则会误判成 bug。**

## v3.3.2 出图五项修正（用户实测报出）

### ① 矢量没跨 180° 环绕
`project()` 直算世界坐标 → 跨 180° 的几何绕远路横穿图幅/跑出画布。
修法：**反环绕**（逐点选离上一点最近的 ±360° 副本）+ **整体偏移**（按与画布
[0,W] 的交集把所有副本都画）。点只取 −1/0/+1 副本（点太多）。
实测中心 170E 修复前右区 0 色 → 修复后 2643 色。

### ② 「px 加 10 倍」不等于 dpi 升 —— 尺寸模型重做
旧：width/height 当自由像素填 → 调大只是把瓦片拉伸，地面分辨率不动。
新：**用户只填纸面 mm + dpi，zoom 引擎反算**：
`zoomNeeded = zoomNow + log2(目标px/屏幕px)`；`zoomTile=floor()`；`upscale=2^(need-tile)`；
瓦片按 upscale 放大铺，底图/矢量同坐标系。实测 dpi96→600 地面精度真升 14 倍。
UI：纸宽mm+纸高mm+dpi按钮组；提示行只报「瓦片级+输出像素+地面覆盖km」，
**不报裸 dpi**（dpi 没配物理尺寸就没意义）。

### ③ 比例尺/指北针/署名默认关（用户要求）

### ④ 切天地图 `setLineDash ... cannot be converted to a sequence`
Leaflet `options.dashArray` 是**字符串**（"4,2"），`ctx.setLineDash` 只吃数组。
天地图/ArcGIS 底图注记边线就带它 → 一切换底图必炸。→ 加 `toDashArray()` 归一。

### ⑤ 填标题 `state.zoomFor is not a function`
`state` 有两处 `Object.assign({}, DEFAULTS)`（初始 + 恢复默认），第二次把挂在
`state` 上的**方法**整个覆盖掉。新 UI 重写（state 只留纯数据）后此问题消失。
**教训：state 对象上别挂方法。**

### ⑥ 顺带修的两个同源坑
- **ArcGIS-海洋 是 LayerGroup 且含 3 个子层** `[天地图世界境界ibo_w, Ocean_Base,
  Ocean_Reference]`，**ibo_w 排第一**（`attachBoundary`）→ `tileLayers[0]` 选中
  覆盖层当底图 + 覆盖层又被 isBase() 排除 → 覆盖层彻底不出现。
  → 收瓦片层前先剔除 overlays/moreOverlays 里的对象。
- **WMS 声明 srs=EPSG:3857 却传度数 bbox** → 服务端当米，落原点一小块 →
  回 3.7KB 空白图，而 loadImage **成功**（report 1/1，图里是空的）。
  → 改 `srs=EPSG:4326`；bbox 折回 ±180（WMS 只认半球）。
  **`report 1/1` 从来不代表"图有内容"**，这是 v3.3.0/3.3.1 就埋的雷。

### ⑦ 健壮性
- GEBCO WMS **服务端本身就慢**（小 bbox 20s、双倍 54s）→ 超时 40s→120s，
  加**屏幕瓦片回退**（复用地图已加载瓦片拼）→ GEBCO 由 0/1 变 1/1。
- `loadImage` 改 `fetch→Blob→createImageBitmap`：`new Image()` 对「无扩展名+长 query」
  的 URL 会**永久挂起**（不 onload 也不 onerror），同 URL 用 fetch 却能拿到 371KB PNG。
  且能识别「服务端返回 XML 错误串」。

### ⑧ 踩到的工程细节
- 多环面必须**同一 path 再 `fill("evenodd")`**，否则内环被当独立面再填一遍；
  为此 `tracePath` 不再自己 `beginPath()`。
- 沙盒里误敲 `.workbududy` 建了目录导致截图路径混乱；`ls` 与 `find` 对该路径
  表现不一致（疑似 OneDrive/SANDBOX 影子），**截图验证以像素统计为准更可靠**。

## v3.4.0 出图：坐标系统一 + 经纬网/标签入图 + 预览限高（用户实测报出）

### ① 跨180°条纹/错位 —— 根因是「两套世界坐标混用」
- `project()` 用**瓦片级**坐标（不含 upscale）；`drawXYZ` 贴瓦片用 `col×TILE×upscale`（含）。
- 两者**只在 upscale===1 时碰巧一致** → 显式传整数 zoom 正常，走引擎 zoom 反算则底图与矢量
  按不同比例摆放 → 跨180°错位 + 密集条纹。
- **为什么之前测试没抓到：测试都显式传了 zoom。教训：测试必须覆盖用户实际走的默认路径。**
- 修法：定义唯一口径 **画布坐标 = 瓦片像素 × S**（S=upscale），project/底图/WMS/影像/矢量全用它。
- 顺带修两个同源错：`metersPerPx` 应 `÷S`（原写 `×upscale`，量纲反了）；
  `scaleFactor` 应 `= W/屏宽`（原 `=upscale`）。
- 验收手段：新增 `report.frame`（出图真实经纬范围），拿 `map.getBounds()` 做**真值**比对，
  6 组组合偏差 ≤0.032%。不变量：`zoomNeeded=zoomNow+log2(W/屏宽)` ⇒ 出图 west/east == map.getBounds。

### ② 经纬度 + 标签入图
- 经纬网间隔**照搬** `Leaflet.Graticule.js` 的 `zoomInterval`；⚠️ 间隔按**屏幕 zoom** 取，
  不是内部 zoomTile（画布与屏幕同范围，密度须一致）。
- 经纬网**刻意不走 project()**：normLng 会把 200° 折回 -160°，而大幅面+低缩放下画布
  会覆盖>1 个世界宽，必须按未归一化经度算 x 才能重复出多份网格。
- 要素标签**读 DOM**（`.station-label:not(.hidden)` + `.leaflet-tooltip`），再用 `k=W/屏宽` 映射。
  两条理由：① 低缩放标签会被隐藏，只有 DOM 知道当前该不该显示（＝"和显示的一样"）；
  ② 线/面标签位置由 Leaflet 算（形心/沿线），重建等于抄一遍还抄不准。

### ③ 预览过高遮挡选项
- CSS 上限必须写在 **canvas 自己**身上：`.box{max-height}` + `canvas{max-height:100%}`
  在 auto 高度父元素上会解析成 `none`（循环引用），**完全不起作用**。
- 预览渲染尺寸也装进 420×200 盒子（原竖版渲染 594px 高纯浪费）。缩略不影响构图
  （zoom 反算保证任何宽度都覆盖屏幕同一范围）。5 个预设预览盒 ≤192px。
