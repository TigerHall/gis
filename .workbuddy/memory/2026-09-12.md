## 补充：快捷区选中态对比度修复（v2.3.7 → v2.3.8）

收尾复核时发现「选中态好像没生效」——**是误报**，踩了个探针坑：

- `getComputedStyle` 在 CSS transition 进行中返回的是**当前插值**，
  改完 `checked` 立刻读 → 拿到过渡起点（旧值）。
  证据：同一元素 `font-weight`（无 transition）已变 600，
  而 `background/border-color/color`（有 transition）还是旧值 → 等 400 ms 后全部正确
- **教训**：断言样式前必须等过渡结束；只给部分属性加 transition 时尤其容易误判

误报里翻出一个**真问题**：

- 选中态边框原用 `--accent`(#99cc99)，与选中底色 #eee 对比度只有 **1.58:1**，
  不满足 WCAG 1.4.11 非文本对比 3:1
- 开关（`.cluster-toggle-switch`）用 `--accent` 是安全的——它有「滑块位移」这个
  非颜色线索；快捷项没有，只靠颜色 + 字重，所以边框必须自己达标
- 改用 `--c-green-text-strong`：浅底 **4.47:1** / 深底 **8.06:1**，两套主题都过
- 未选中边框 1.32:1 / 1.49:1 保持不动 —— 与既有 `.toggle-bar` 一致，
  且控件靠文字标签识别，不依赖边框（1.4.11 不适用）

## （b）快捷区回归「快捷键」定位 + 点击手感（v2.3.8 → v2.3.9）

**用户反馈两点**：① 3D视图 / 经纬度格网 / 深色模式 / 显示位置 不该占常用位，
「所有的设置在地图设置里应该都有，相当于常用功能只是把下面的地图设置开关的快捷键」；
② 点击手感怪。

**第①点暴露的真问题**：上一轮把 8 项置顶后，**它们就从「地图设置」里消失了**
（渲染时 `if (!q.quick) continue` 过滤掉）—— 同一组设置被劈成两处，且找不到「全部设置」的地方。
修法是改数据模型而不是改文案：**面板保留全量 21 项，快捷区变纯入口**。

- 快捷项 `<label>+透明 checkbox` → `<button aria-pressed data-quick-for>`；
  点击 `master.checked = !checked` + `dispatchEvent("change")`，原有链路（持久化 /
  enable·disable / 徽标）零改动就跑通
- 反向同步靠 `document` 一条 change 委托（比原来只在 quickBar 上监听更全）
- **差点写错的地方**：一开始把面板里 quick 项渲染成「无 id 的镜像 checkbox」，
  以为快捷区那个是主控件 —— 那样 `initToggle` 会找不到元素、开关全废。
  **主控件必须在面板里带 id**，快捷区不能持 id。实测全文档 0 重复 id。
- 移出 4 项后补 4 项高频的凑成 4×2：鼠标坐标 / 更多底图 / 识别粘贴 / 读取高程
- 「操作」分类只有按钮，徽标统计不出 `x/y` → 退化成「1 项」

**第②点根因**：快捷项是铺满整块的**透明 checkbox**，浏览器原生的按下反馈被透明层吃掉，
配上 120ms 线性渐变 = 点下去「没反应、然后慢慢变色」。改成 button 后显式给：

- `:active { transform: scale(.94); transition-duration: 0s }` —— 按下瞬时到位，
  松手靠普通规则的 0.12s 弹回。**跟手感的来源是「立刻」而不是「更快」**
- `touch-action: manipulation`（去移动端 300ms 双击判定）
- hover 收进 `@media (hover:hover)`（触摸屏点完不再粘高亮）
- `:focus-within` → `:focus-visible`（鼠标点完不留焦点环）
- 焦点环 `--accent` → `--c-green-text-strong`（#99cc99 对 #fafafa 才 1.8:1）

**验证**（`verify-quick-239.js`）：快捷区 8 项全 `BUTTON`/0 内嵌 input、面板 20 开关+1 按钮、
0 重复 id、双向同步 + localStorage 落盘、按压 `matrix(0.94,…)`、焦点环 `rgb(58,116,58)`、
选中态 4.84:1、两个 `data-action` 入口都触发导出、0 console error；
另跑上一轮全量回归（历史影像 196 时相 / 测量导出 3829.258km / JSON 下载）全绿。

**截图**：`docs/shots/quickbar-{light,dark,pressed}.png`。


## 第三轮：滚动条槽位常驻预留（v2.3.9 → v2.3.10）

**用户反馈**：「常用功能、地图图层等，当出现竖向滚动条的时候，会让界面收窄，感觉不美观，
我觉得可以直接预留滚动条的位置」。

**问题量化**：侧栏 300px 固定，`.panel-scroll` 是唯一滚动容器。内容从「放得下」变
「放不下」时，滚动条出现 → 内容可用宽度 283px → 273px，快捷区 4 列网格、开关文字、
图层名整体横向抖 10px；收起时再抖一次。溢出阈值在视口高 1100↔1050 之间。

**修法**：统一 `scrollbar-gutter: stable`（**不要用 `overflow-y: scroll`** ——
那会把滚动条轨道一起画出来）。9 处：`main.css`(.panel-scroll/.search-results)、
`dialog.css`(.dialog-body/.md-toc-list/.feature-popup-body)、`geojsonloader.css`
(.dlg-tab-content)、`feature-panel.css`、`pointdrop.css`、`Leaflet.LegendControl.css`。

**顺带修掉两个真问题**：

1. `.app-dialog .dialog-body` 上限 `min(80vh,600px)` **没算对话框头部**(~57px)，
   视口 <525px 时 `.app-dialog` 自身也溢出 → 出现「对话框滚动 + 正文滚动」两层嵌套，
   且外层滚动条一出现就把正文推窄 15px。改为 `min(600px, calc(100vh - 140px))`
   → 实测对话框在 900→380px 视口下 `clientH === scrollH` 恒不溢出，
   且视口 ≥700px 时取值与原先**完全一致**。
2. `.app-dialog .dialog-body pre` 只写 `overflow-x: auto` → 浏览器把 `overflow-y`
   由 `visible` 计算成 `auto`，被审计误判成「未预留的纵向滚动容器」。显式
   `overflow-y: hidden`（代码块无 max-height，本来就不可能纵向滚动）。

**未改（有意）**：`leaflet.css` 的 `.leaflet-popup-scrolled` / `.leaflet-control-layers-scrollbar`
本项目都没用到（无 `maxHeight` popup、无 `L.control.layers`）；后者还是 `overflow-y: scroll`
恒占位。`.layer-dialog` 本体仅视口 <266px 才可能溢出，不值得加死代码。

**验证**：

- ⚠️ **坑**：Playwright 默认给 Chromium 传 `--hide-scrollbars`，headless 下滚动条
  **根本不渲染**，`scrollbar-gutter:auto` 永远不占位 → 不加
  `ignoreDefaultArgs: ["--hide-scrollbars"]` 会得到「抖动 0px」的假阴性。踩了一次。
- ⚠️ **坑**：本页 `#panelScroll` 默认内容就比一屏高（scrollH 1010 > clientH 825），
  900px 视口下造不出「不溢出」状态。改为**扫描视口高度**（1500→700）跨阈值对照。
- 结果：`auto` 283→273（跳 10px），`stable` 273→273（恒定）；gridW / 快捷项宽 /
  子元素右边缘同步验证。
- 双通道全量审计：DOM 实测 6 OK / 1 N-A / **0 BAD**；CSSOM 静态 9/9 合规。
  审计逻辑要点：**不能只看「有没有声明 stable」，要看「会不会真的溢出」** ——
  加了 OK / N-A（实测恒不溢出）/ BAD 三分类，`dialog#_mdDialog` 归入 N-A。
- 功能回归全绿，0 console error。

**截图**：`docs/shots/gutter-compare.png`（四态 2×2 对照 + 红色内容右边缘标线）+
`gutter-{auto-fit,auto-over,stable-fit,stable-over}.png`。

**产出**：把「滚动条槽位审计」补进用户级技能 `ui-a11y-contrast-audit`
（`scripts/scroll-gutter-audit.js`）。

## 2026-09-12（d）— 滚动条槽位改为「懒预留」（v2.3.10 → v2.3.11）

**起因**：用户看到图例右侧的空白，问「这也是留给滚动条的么？这个感觉没必要，
因为一般不会出现，出现了让其可以变化也无所谓」。随后进一步给出方案：
「如果统一处理的话，也可以出现滚动条后，挤占了之后不再回去，只要不是来回动就行」。

**判定上一条的错**：无条件 `scrollbar-gutter: stable` 让「几乎不溢出的容器」
白留一条。实测图例 6 条（不溢出）：外框被撑到 95px，内容其实只要 85px，
行右侧留白 11px（应只 1px 边框）。判据应是**会不会经常在 溢出↔不溢出 之间往返**。

**实现** `assets/scroll-gutter-guard.js`（懒预留）：

- 首次真的溢出 → 打 `data-scroll-guttered` → 常驻；CSS 只留一条属性规则在 main.css
- 关键：打标记那刻滚动条已在占位 → 引 stable 零视觉变化；之后不还回去 → 无往返抖动
- Discovery：文档级 `MutationObserver`(childList+subtree) 定向 `querySelectorAll(新增子树)`
  + `rec.target.closest(SELECTOR)`，合并到 **rAF**（仍在本帧绘制前）；外加
  DOMContentLoaded/load/resize(防抖150ms)/600·2000·5000ms 粗扫
- 标记进 `WeakSet`，`check()` 先查后量 → 不反复重排。公开 `window.ScrollGutterGuard`

**实测三态（每态都验证到位）**：

| 场景 | 标记 | 预留 |
|---|---|---|
| 图例 6 条 / 属性表格 2 行 | 否 | **0** |
| 图例 25 条 / 属性表格 20 长行 | 是 | 10 / 15px |
| 再回到 6 条 / 2 行 | 是 | 10 / 15px ← **不还回去** |
| `.panel-scroll` | 加载后自动标记 | clientW 在视口 1500→520 恒 273 |

顺带：图例补 `scrollbar-width: thin` + `scrollbar-color`（原先系统粗滚动条在
240px 箱子里占 1/6）。回归全绿，0 console error。

**踩的坑**：

- ⚠️ **同一文件并行 Edit 会丢改动**（第二次踩）：`.md-toc-list` 那条 `stable` 没删掉，
  工具报成功但没落盘。同文件多处改动必须串行
- ⚠️ **截图脚本别手动 `removeAttribute` 去「重置」守卫**：WeakSet 已记账，
  标记过就不再补属性 → 后三态全部失真。改成每态重开页面自然驱动
- ⚠️ **画标注要在元素入文档之后**：`board` 未 append 时克隆体未布局，
  `offsetWidth` 全是 0 → 标注宽度算成 0 直接不画（排查了一轮）
- ⚠️ 克隆体自身有 `overflow-y:auto`（另一轴计算成 auto）→ 子元素绝对定位会被裁掉，
  标注改画在**未缩放的父容器**里再按 scale 换算坐标

**截图**：`docs/shots/legend-gutter-compare.png`（2 倍放大对照板，红色带标出槽位）+
`legend-lazy-{forced-stable,lazy-fit,lazy-overflow,lazy-back}.png`。

## 2026-09-12（e）— CHANGELOG 引用改图片语法（v2.4.0）

**起因**：用户选了我建议的 A 方案 —— 「CHANGELOG 的引用改成图片语法」。

**踩到的必然坑：`marked` 不做路径重写。**
`showMarkdown()` = `body.innerHTML = marked.parse(md)`，产出的
`<img src="shots/x.png">` 直接进弹窗 DOM → 浏览器按**页面 URL** 解析 →
去请求站点根的 `/shots/x.png`，必 404。

- **差点用错方案**：直接写成 `docs/shots/x.png` 能过 App 内这一关，
  但在 GitHub 上（文件本身在 `docs/`）会解析成 `docs/docs/shots/` → 两边只能保一边
- **正解**：`resolveRelativeImages(root, docUrl)` —— 按**文档自身目录**补前缀。
  Markdown 语义正确，于是 App 内与 GitHub **同时成立**，且以后 `docs/` 下
  任何文档写相对图都不用再操心。只处理相对路径，`/` `//` `http:` `data:` `#` 不动

**点击放大**（对照图是 2 倍图，`legend-gutter-compare.png` 达 3420×1860，
缩进 680px 弹窗只剩 18%）：

|---|---|---|
| 默认 | 680px | 617px |
| 放大 | **1344px** = `min(1840px,96vw)` | **3422px**（原始像素，横向拖动） |

- `bindImageZoom(body)`：切 `img.md-zoom` + 按有无放大图给 `<dialog>` 切 `.md-zoomed`
- **顺带修掉一个隐藏阻断**：`.dialog-body` 原本 `overflow-x: hidden`（防宽表格撑破），
  放大态下用户**拖不到大图右侧**。补 `.app-dialog.md-zoomed .dialog-body{overflow-x:auto}`
- ⚠️ **探针漏判**：`overflow:hidden` 的盒子 `scrollLeft` 仍可被脚本改写 ——
