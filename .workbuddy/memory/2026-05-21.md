# 2026-05-21 工作记录

## 修复反子午线大面渲染错误

**问题**：跨度大（>180°）或起点在 ±180° 附近的多边形/线在地图上渲染错误，出现在错误位置或形状变形。

**根因**：`geo-utils.js` 中 `fixRingCoords` 的旧实现，起点被强制归到 `[-180, 180]`，但当面的质心靠近 ±180° 时，后续展开方向整体偏移，导致整个面渲染到错误位置。

**修复**（`assets/geo-utils.js`）：

1. **第一步**：用向量均值法（sin/cos）计算环的真实质心经度 `centerLng`，避免 170° 和 -170° 均值算成 0 的问题。
2. **第二步**：起点先归一化到 `[-180, 180]`，再根据 `centerLng` 偏移，让起点落在离质心最近的展开值（不再硬拉到 `[-180, 180]`）。
3. **第三步**：标准"展开"策略保持不变（消除相邻点 >180° 的跳变）。
4. **第四步**：加了反转面检测：若展开后经度跨度 >350°，说明整体偏移过大，把中心偏移 ±360° 拉回合理范围，防止填充算法把整个地球都填满。

**测试通过场景**：
- 正常跨子午线（170° → 185°）✓
- 起点在 178° 附近的面 ✓  
- 超大面（跨度 320°，-160°～160°）✓
- 原本坐标已超出 180° ✓

## 二次修复：fixRingCoords 深层 bug（180° 归一化问题）

**问题**：上次修复仍有遗留 bug——坐标中包含恰好 `180°` 的点时，归一化会把它变成 `-180°`，导致：
- 向量均值计算被 -180° 主导，得出错误质心（如 -169°）
- 起点被错误地偏移 -360°（从 160° 变成 -200°）
- 整个太平洋大面展开到 -200~-100°，完全错位

**根因**：旧版展开循环用 `((dLng%360)+360)%360` 归约 delta，这个公式对 `dLng=-360` 输出 0，但在 180°→-180° 场景下产生错误 delta；同时质心计算里直接用原始坐标的 sin/cos（未先归一化）。

**修复**（`assets/geo-utils.js` `fixRingCoords`）：

1. **质心计算**：先把每个点归一化到 `[-180,180]` 再求 sin/cos（而非直接用原始坐标）
2. **展开循环**：改为先归一化 `cur[0]`，再用 `if(dLng>180) -=360; else if(dLng<-180) +=360;` 直接归约 delta（不再用 mod360 公式）
3. **删除反转面检测**：不再需要（新算法对太平洋大面能正确展开到 160~260°，Leaflet worldCopy 处理超出范围的坐标）

**测试验证**：13 个场景全部通过，最大跳变 ≤180°（保证 Leaflet 不画穿越地图的长线）

## 三次修复：fixRingCoords 彻底重写（北冰洋/南极洲形状反转）

**问题**：V2 修复对大西洋、太平洋正确，但北冰洋、南极洲等覆盖全球经度的面出现形状反转——展开方向由第一个点位置决定，导致面的内外反转。

**根因分析**（经过 12 个版本迭代）：

1. **向量均值(atan2)在子午线附近彻底失效**：当面均匀分布在 ±180° 两侧时，sin 正负抵消，cos 为负（因为 180° 的 cos=-1），atan2(≈0, <0) = ±180°，无法区分面的主体方向
2. **中位数也失效**：当面主体跨 0° 线（如 120°→-110°），中位数在 0°~120° 之间，但展开方向应该保持原坐标范围
3. **「最小跳变」假设根本不成立**：这个假设要求相邻点走最短路径，但对大跨度面（如 160°→-160°），最短路径=向东 40°，而实际应该是保持原坐标不展开
4. **跳变分类阈值（|prev|+|next| > 300）过于激进**：把窄跨子午线面（170°→-170°）也当成边界跳变

**最终算法**（V12，"最优展开"）：

完全抛弃质心/中位数/方向判断，改用**穷举+能量最小化**：

1. 归一化所有坐标到 `[-180,180)`（180° → -180°）
2. 如果无跳变或只有 ±180° 边界自跳变（|delta| ≥ 355），直接返回
3. 否则穷举 145 个起始偏移（每 5° 一步，-360°~+360°）
4. 每个偏移做标准展开，计算**平方跳变能量之和**（Σ delta²）
5. 选能量最小的展开结果

**平方能量的关键作用**：避免「均匀错位」——线性能量对等差展开和大面翻转不敏感（能量相同），平方能量会惩罚大跳变更重，使得"保持原坐标不变"（能量=跳变平方）比"整体偏移180°"（能量=每个小步进都变成跳变）更优。

**性能**：O(145 × n)，对万级点数环 <1ms，对 GeoJSON 全量调用可能有影响但可以接受。

**测试**：15 个场景全部通过（北冰洋、南极洲、太平洋、窄跨子午线、小面、大面等）

## 四次修复：fixRingCoords 改为 Feature-level Shift 方案（解决正常面被错误展开）

**问题**：V3 "穷举+能量最小化"策略过于激进——本来正常的面（太平洋、大西洋等不跨线的面）也被错误地展开拉伸，横跨整个地图。

**根因**：以 ring 为单位做穷举展开，判断条件（检测到 |delta| > 180 就穷举）太宽松。正常不跨线的面也可能因数据噪点或面很大而产生 >180° 的 delta，穷举会改变整个 ring 的坐标，破坏形状。

**行业方案调研**：
- **Split（QGIS/GDAL）**：在180°处切割成 MultiPolygon，拓扑正确但改变几何类型
- **Shift（Leaflet.Antimeridian 插件）**：统一偏移坐标使多边形连续，保持原始几何类型

本场景更适合 **Shift** 方案，因为不需要拓扑计算、Leaflet 允许坐标超出 [-180, 180]、不改变几何类型。

**修复**（`assets/geo-utils.js`）：

1. **核心设计变更**：以 **Feature 为单位**判断偏移方向，而非以 ring 为单位
2. **`computeFeatureShift` 函数**（新增）：
   - 收集 Feature 所有经度，归一化到 [-180, 180)
   - 若经度同时分布在正负两侧（有 >90° 和 <-90° 的点），可能跨线
   - 比较正负两侧点数量，把点少的一侧偏移到点多的一侧
   - 偏移后验证相邻点 delta，若仍有 >180° 跳变则回退（偏移=0）
3. **`fixRingCoords` 函数**（重写）：
   - 接收 `featureShift` 参数
   - 若提供了统一偏移，直接应用（保持坐标相对关系）
   - 否则仅做归一化到 [-180, 180)，不做展开
4. **`fixGeometryCoords` 函数**：先调用 `computeFeatureShift` 计算偏移，再传给 `fixRingCoords`

**关键区别**：
- V3：每个 ring 独立穷举 145 个偏移，可能破坏正常面
- V4：每个 Feature 统一判断一次偏移（+360/-360/0），所有 ring 同步偏移，保持形状

## 最终方案：放弃 fixAntimeridian，改用三副本（worldCopy）方案

**结论**：经过 V1~V4 四轮迭代，各种坐标修正方案都有边界 case 导致正常面被错误处理。最终采用**最简单可靠的三副本方案**——不做任何坐标修正，直接在 [-360, 0, +360] 三个位置各渲染一份 GeoJSON，让跨 180° 的面自然连续显示（和底图瓦片效果一致）。

**改动**：
1. **`geojsonloader.js`**：移除全部 4 处 `window.GeoUtils.fixAntimeridian()` 调用，直接使用原始数据
   - 第 683 行：`loadGeoJSONLayer` 预置图层加载
   - 第 879 行：颜色模式切换后重建
   - 第 1226 行：颜色弹窗字段提取
   - 第 1513 行：用户上传图层
2. **`buildGeoJsonLayerGroup`**：已有三副本逻辑（第 374 行 `offsets = [-360, 0, 360]`），无需修改

**验证**：`test.html` 测试页确认三副本方案对所有面类型渲染正确、拖动连续

## GeoJSON 加载修复

### Pacific_FZ.json 空坐标崩溃
`geo-utils.js` `processCoords` 未做空数组防御，`Pacific_FZ.json` 中 `#6 Tharp` 坐标为 `[]`，导致 `c[0][0]` 报 TypeError。修复：入口加 `if (!c || !c.length) return;`。

### Canvas 点位不渲染（需手动缩放才显示）
`Leaflet.MarkersCanvas.js` 中 `setFeatures()` 在 `addTo(map)` 之前调用，`_redraw(true)` 因 `_map` 为 null 被跳过，之后 `onAdd` 未触发重绘。修复：在 `onAdd` 末尾检查已有 features 则补调 `_redraw(true)`。
