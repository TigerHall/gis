## 2026-09-13 — 平台拓展方向盘整 + `geo-config.js` 拆成「引擎 / 清单」两层

### 起因

用户提出平台后续拓展方向：**数据托管（别人把数据放上来）+ 定制交付（平台迁移）**。
盘整现状后确认三个断点：

1. **无服务端** —— 全站只有一次 `fetch("service-worker.js?")` 做版本检查（`app.js:1103`），
   数据入驻完全靠人肉：收邮件 → QGIS 转 GeoJSON → 改配置 → 部署
2. **无租户隔离** —— 一套配置 = 一个站，做定制只能 fork 整个仓库
3. **无计量交付** —— 授权是硬编码 5 个激活码（`app.js:11` `_PR_CODES`），发一个码要改代码部署

用户明确三个约束：**科研寄存 + 付费定制分阶段 / 交付独立站点 / 尽量不加后端**。
方案定为「纯静态多租户」：一套引擎 + 每租户一份清单 + COS 按前缀隔离数据。

本次先落地**第 0 步**：把图层清单从源码里外置。这是 A（托管）/ B（定制）/ C（嵌入）
三条路共同的必经关口。

### 关键发现：耦合面极小

动手前先摸清了清单的全部消费点，只有 **5 处**，比预想干净得多：

| 消费点 | 位置 | 用法 |
|---|---|---|
| `window.geoJsonGroups` | `geojsonloader.js:3152` | 同步 `forEach` 建图层树 DOM |
| 路径 4 个变量 | `geojsonloader.js:1449 / 1452 / 3091 / 3248` | 主路径 + 偏移回退 |
| `window.PLACE_REGISTRY` | `app.js:466` | 深链地名查询 |

清单只在 `generateLayerItems()`（3107）里被读一次，而它在 `initGeoJsonLayer()`
（5771）内、由文件末尾 6093 行调用 —— 全部同步执行。这个事实决定了拆法。

### 做法：按「数据 / 逻辑」分层，不引入异步

拆成两个文件，加载顺序不可颠倒：

```
layers.js       ← 数据层：window.geoJsonGroups = [...]（原 96-420 行原样搬）
geo-config.js   ← 逻辑层：路径解析 + 清单兜底 + PLACE_REGISTRY
```

**放弃了「改成异步 fetch JSON」的方案**。理由：`window.geoJsonGroups.forEach`
是同步的，改异步就要把 `initGeoJsonLayer()` 挂到 Promise 上，动到初始化时序
（那是本项目的历史雷区）。当前用 `<script src>` 顺序加载，**零时序改动、
零行为变化**，第 0 步的风险降到接近零。

同时加了**清单兜底**：

```js
window.geoJsonGroups = window.geoJsonGroups || [];
```

意义：`geojsonloader.js:3152` 直接 `.forEach`，万一清单文件缺失就是
`TypeError` 直接白屏。有了兜底，页面至少能打开（只是没图层）——故障可见可控。

## 2026-09-13（b）— 用户质疑「layers.js 有必要单出来吗」，用实验回应 + 一处说法修正

### 质疑

用户观点：*「修改的话也就我修改，其他人应该不会动的」* —— 如果只看**谁改**，
拆不拆确实没差别，单文件搜起来还更集中。这个质疑是站得住的。

### 实验：拆分到底买到了什么

同一份 `geo-config.js`（未修改，响应 200），只换清单引用，两个站点并存
（`artifacts/verify-why-split.js`）：

| 站点 | 清单来源 | 分组 | 图层项 |
|---|---|---|---|
| 主站 `/` | `assets/layers.js` | 8 | 59 |
| 客户B（模拟） | `artifacts/tenant-demo.js`（11 行数据） | 1 | 3 |

→ **拆分的价值不在「谁改」，而在「清单能被单独替换」**。要做「引擎共享、
配置分离」的多站点，清单就必须是独立文件 —— 这是硬约束，不是风格偏好。

反过来说：**若短期不做多租户，单文件更省事**，这个判断是成立的。

### ⚠️ 修正上一轮的一个不准确说法

我先前说「清单可热更新、改完不发版」—— **在当前的相对路径方案下不成立**。
原因：`dupal.cn` 本身就是 COS 静态网站域名，`./assets/layers.js` 是**同域**文件，
会被 SW 预缓存（已在 `STATIC_ASSETS`）→ 改 COS 上的内容，老用户看不到，
**仍要等 `CACHE_NAME` 变化**。

要真正热更新，清单必须走**跨域绝对 URL**（如
`https://dupal-1258052757.cos.ap-shanghai.myqcloud.com/...`），
因为 `service-worker.js:134` 明确 `if (!url.startsWith(self.location.origin)) return;`
跳过跨域请求。

→ 结论：**「清单外置」和「清单热更新」是两件事**，后者还需要换 URL + 放弃离线可用性
（跨域不进 SW 缓存 = 离线时取不到清单）。这个取舍留给第 3 步（租户化）时决定。

#### ⚠️ 踩到的两个坑（都已修，务必记牢）

1. **注入的 `<style>` 会被 main.css 压掉**
   `geo-config.js` 在 `<head>` 里（`index.html:57`）**比 `main.css` 的 `<link>`（:60）更早**执行
   → 此刻 link 还没解析，`document.head.appendChild(style)` 注入的样式排在它**前面**
   → 同优先级（都是 `:root` = 0,1,0）下**后写的 main.css 胜出**，品牌色完全不生效。
   **修法**：选择器抬高一档 → `:root:root` / `:root[data-theme="dark"]`（0,2,0）。
   不再依赖插入顺序。
2. **抬高优先级后，浅色规则会在深色下照样生效**
   把 main.css 的深色 `--c-statusbar:#111111` 一起压掉了。
   **修法**：`--c-statusbar` 单列一条 `:root:not([data-theme="dark"])`（只在浅色写），
   深色交回 main.css 自己管。
   > 注：不能改用 `documentElement.style`（内联样式）—— 它优先级高于一切选择器，
   > 会把深色取值**一并**压掉，深色下仍是浅色品牌色。

## 2026-09-13（h）— 弹窗按钮改「事件委托 + 点击时现取要素」（v2.6.3）

### 用户报的两件事
1. 点要素的「⚲ 缩放至」没用（详情正常）。

### 机理（以后改任何面图层颜色都看这里）
- 面要素**不写 `colorMode` 时默认 `"sequential"`** → `GeoUtils.getFeatureColorByIndex(idx)`

- 想要单色 = **`color: "#xxxxxx"` + `colorMode: "single"`**（缺 `colorMode` 则 `color` 不生效，
  因为 sequential 分支根本不读 `layerColorMap`）。
- 面要素填充不透明度有**硬上限 0.45**：`fillOpacity = Math.min(layerOpacity, 0.45)`；
  而**描边 opacity 用未截断的 `layerOpacity`**（默认 0.8）。所以"调透明度"调的是两个不同的值。
- 面要素描边色 **全站硬编码 `#555`**（`getGeoJsonStyle()` 最后那个 return），目前无配置字段。

但图层个性化设置的 key 是 `dupal_layer_set_<cbId>`（`:2606`），**同前缀** → 一起被算进去。
实测：`localStorage.clear()` 后只写一个 `dupal_layer_set_layer_probe`、0 个图层勾选 →
刷新照样弹「检测到上次访问时打开的图层」；什么都不写则不弹。用户只要调过一次某图层的
颜色/透明度/名称字段，**此后每次打开都被问**。更糟的是点「不恢复」会走
`clearAllLayerStates()`，其第一个循环（`:5819-5829`）因同一条宽前缀把 `dupal_layer_set_*`
**一并删掉** → 用户的个性化设置被当成「待恢复的图层」清掉。
修法：判据改成 `key.indexOf("dupal_layer_") === 0 && key.indexOf(LAYER_SETTINGS_PREFIX) !== 0`
（或把设置键换前缀，如 `dupal_lset_`）。

**② 覆盖层记忆在坏 JSON 后永久静默失效 —— `persistOverlay` 不自愈**
`basemap-manager.js:496-504` 是「读-改-写」，`JSON.parse` 抛异常 → `catch (ex) {}` 吞掉 →
`setItem` 永不执行。初始化（`:471-476`）也只在内存里 `savedOverlays = []`，**不修存储里的坏值**。
实测：把 `dupal_overlays` 写成 `{oops` 后勾选「天地图地名标注」→ 图层**上了图**但存储仍是不变
的坏值（界面与存储不一致）；清掉后再勾选则正常写入；坏值刷新后覆盖层不恢复且坏值永留。
修法：解析失败时 `removeItem` 并重置为 `[]`。

### 追加：设置面板「已开/总数」徽标计数修准 — v3.0.4

用户报「高级功能激活后高级组还显示 0/5，再开一个变 2/5，再次进入又变 0/5（实际 2/5）」，
并要求「这个计数的问题可以写的稳妥一点」。

**根因**：徽标读 checkbox 实时状态，但开关在**面板渲染之后**才恢复 ——
`initToggle` 是程序化赋值（不触发 change），cluster/label 由 geojsonloader 更晚恢复。
「高级」组五项默认全关 → 「渲染时算一次 + 只监听 change」永久停在 HTML 默认值。
「显示」组同样不准（默认 2/6，关掉聚类刷新仍显示 2/6），只是没人注意。

**修法（收敛成幂等入口，而不是靠每个调用点记得触发）**
- `requestSubBadges()` 用 **rAF 合并**，同一帧改 20 个开关只重算一次，重复调用零成本
- 挂进 `window._syncQuickStates()` —— 快捷区与徽标读同一批 checkbox，一处挂钩全覆盖
- `initToggle()` 在**副作用跑完后**再同步一次（premium 未激活时 enable() 会强制取消勾选）
- 激活成功 / `premiumReset()` / 深色预设 / 跨标签 storage 同步 全部补同步
- `geojsonloader.js` 恢复 cluster/label 后主动 `window._syncQuickStates()`
- **兜底：`<details>` 的 `toggle` 事件不冒泡但走捕获阶段** → 用
  `body.addEventListener("toggle", fn, true)` 捕获，展开/收起时再刷一次

**实测 29/29**。脚本 `~/.workbuddy/binaries/node/workspace/badge-audit.js`。
**判据写成「徽标 === 该组实际勾选数/总数」而不是固定数字** —— 以后加开关不会漏。
