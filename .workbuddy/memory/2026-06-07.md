## 搜索功能修复
- `buildSearchIndex` 增加 `.catch()` 处理 IDB 缓存异常降级（原代码 IDB 拒绝时 callback 永不触发 → 索引不构建 → 提示卡死）

- 搜索输入框增加 `:disabled` CSS 样式（浅色/暗色模式），索引构建时视觉可辨识

## 搜索要素功能再次修复（双重保障）
- 要素搜索第二阶段改为「倒排索引优先 + 全量特征扫描兜底」的双重策略
  - 方案A：原有倒排索引匹配（精确 token + 模糊子串）
  - 方案B：方案A未命中时，直接全量遍历 `si.features` 做 `indexOf` 属性值匹配
  - 确保即使索引构建有问题，要素搜索始终有结果返回
- 修复模糊搜索空 `candidateSets` 时误判为匹配的问题
- 要素搜索第二阶段改为双源策略：优先 `searchIndexMap`，兜底 `featureCache`

## 搜索索引修复（根因查明）
- 根因：UI 初始化时（第2007行）`searchRegistry.push` 提前占位了所有图层的 checkboxId
- `onDataLoaded` 中 `if (!searchRegistry.find(...))` 永远为 false → 搜索索引永不重建
- 修复：改为判断 `if (!searchIndexMap[checkboxId])`，仅当真正有索引数据时才跳过

## 用户上传图层持久化
- Leaflet.GzIdbLoader.js 新增 `delCache(key)` 和 `deleteSearchIndex(cacheKey)` 方法
- 用户上传图层时：保存 GeoJSON 数据到 IDB（key: `user_geo_<persistentId>`）
