### 一、Cesium 南北极「空洞」——查清了，不做垫图（用户已拍板放弃）

用户原本问能否用极区底图垫在洞下面。**结论：洞是地形不是影像，垫图无效。**

| 垫图方案 | 极区近黑像素 |
| --- | --- |
| 不加垫图（仅单层底图） | **0%** |
| 极冠条带（20°~90°，`SingleTileImageryProvider`） | 97.8% |
| 全球单张等经纬图（±90°，同 provider） | 97.8% |
| 手写「任何瓦片返回同一张图」的 provider | 100% |

- **根因**：默认地形 ArcGIS World Elevation 3D 是 Web Mercator 瓦片（上限 ±85.0511°）。
  转储 `globe._surface._tilesToRender`：相机 89.5°N 时视锥内纬度 >80° 的地块只有一个
  `L1 lat[0,85.05]`，**极点附近一个地块都没有**。换 `EllipsoidTerrainProvider`（±90°）
  后立刻出 112 个 `lat[84.37,90]` 地块。
- **反直觉点**：单层底图时近黑 0% —— Cesium 会把基底层边缘瓦片拉伸盖住极点；
  **一旦在底下多垫一层，这个兜底就失效**（0% → 100%）。所以垫图有副作用。
- 真能解的两条路：给 Cesium ion token / 进极区切椭球地形 —— 都改地形表现，不做。
  结论已写成注释留 `cesium-viewer.js` `syncBasemap()` 上方。
- 回滚：删掉 `cesium-pad-north/south.jpg`、`cesium-underlay.jpg`、`make-cesium-polepad.js`、
  `make-cesium-base.js`；`geo-config.js` 里的 `cesiumPads` / `cesiumUnderlay` 配置段一并撤销。

### 二、底图控件新增「无底图」（用户当前需求）

`BASEMAP_CONFIG.noneLabel = "无底图"` → 一个空 `L.layerGroup([])` 混进 `allBaseLayers`，
**靠「底图区是单选」这一个特性**自动卸掉上一张底图，不需要手动遍历卸载。

- 位置：`getVisibleBaseLayers()` 在「默认子集 / 更多底图」过滤**之后**追加 → 恒在末尾。
- 状态外显：`syncNoneState()` 打 `body.basemap-none`（`rebuildLayerCtrl()` + `baselayerchange`
  各同步一次）→ `main.css` 把 `#map` 背景从 Leaflet 默认 `#ddd` 换成 `--c-bg`，
  否则深色主题下会亮白一块。
- 记忆：它就是普通底图名，走 `OGVStorage.KEY.BASEMAP`。
- 3D：导出 `BasemapManager.noneName`，`syncBasemap()` 认出来就不铺影像，只留覆盖层。
- 传空串 = 隐藏该项，引擎侧零硬编码。

**验收（无头浏览器 7 项，`verify-none-basemap.js`）**：控件最后一项确为「无底图」；
选中后底图瓦片 84 → 0、`body.basemap-none` 为真、`#map` 背景为主题色、16 条矢量 path 照常；
刷新后记忆为「无底图」；切回 ArcGIS-海洋 瓦片恢复 84；3D `imageryLayers` 只剩覆盖层。

**两个假警报（都查清了，不是 bug）**：
1. 「无底图下还有 28 个瓦片 `<img>`」→ 是用户勾选的**覆盖层「天地图全球境界」**（`z=18`），
   底图瓦片是 `z=19` 那 56 个，已归零。
2. 「3D 真实底图也只有 1 层」→ **停用→再启用**这条路径下基底层会缺（既有怪癖）。
   换成「3D 激活状态下切 2D 底图」实测：ArcGIS-海洋 = 2 层（Ocean 底图 + 境界覆盖层）、
   天地图影像 = 2 层、无底图 = 1 层（只剩覆盖层）。`probe-3d-base.js`。
