## Leaflet.VectorGrid 测试（test.html）

### 技术路线
- 用 `L.vectorGrid.slicer()` 替代手动三副本 `shiftLng()` + `L.geoJSON`
- VectorGrid 自动处理世界循环（跨 180° 反子午线重复），不需要手动偏移

### 关键发现
- VectorGrid 的 `L.SVG.Tile` 重写了 `onAdd = L.Util.falseFn`，导致 `this._drawing` 从未被设置为 `true`
- `L.SVG._updatePoly()` 开头有 `if (!this._drawing) return;`，因此所有 fill 渲染被跳过（只有 stroke 能看到）
- **修复**：在 `rendererFactory` 里设置 `r._drawing = true`

### 实施代码
```js
rendererFactory: function(tileCoord, tileSize, opts) {
    var r = L.svg.tile(tileCoord, tileSize, opts);
    r._drawing = true;
    return r;
}
```

## Shapefile 中文乱码问题踩坑记录

### 现象
- 中文 Shapefile（字段名/字段值）在属性表中显示乱码
- 手动创建 `.cpg` 文件（内容为 `UTF-8`）放入后仍然乱码
- ArcGIS Pro 导出的 `.cpg` 文件可以正常读取

### 根因分析
1. **`shp.js` 的 `createDecoder` 逻辑**：无 `.cpg` 时默认用 UTF-8 解码，但中文 DBF 通常是 GBK/GB2312
2. **浏览器 `TextDecoder` 不支持 `GB2312`**：只支持 `GBK`，`new TextDecoder('GB2312')` 会抛异常，回退到 UTF-8 → 乱码
3. **`.cpg` 文件格式要求严格**：
   - Windows 记事本默认保存为 UTF-8 with BOM，BOM 会导致 `shp.js` 读取编码名称失败
   - 内容不能有换行符或多余空格（虽然 `trim()` 处理了，但 BOM 无法被 `trim` 去掉）
4. **编码标准不统一**：
   - 老版 ArcGIS / 中文 Windows：`GB2312` 或 `GBK`
   - ArcGIS Pro（新版）：统一 `UTF-8`，并生成 `.cpg` 文件
   - QGIS：取决于导出设置

### 尝试过的方案（均不理想）

#### 方案 1：修改 `shp.js` 源码 → 无效
- 实际运行的是 `shp.min.js`，修改 `shp.js` 无意义

#### 方案 2：在 `geojsonloader.js` 中用 JSZip 注入 `.cpg` → 有缺陷
- 注入 `GBK`：对 UTF-8 数据会二次破坏
- 注入 `gb2312`：`TextDecoder` 不支持，回退 UTF-8 → 仍乱码
- 读取已有 `.cpg` 并替换 `GB2312` → `GBK`：逻辑复杂，且 `.cpg` 内容可能有 BOM

#### 方案 3：前端自动检测编码（如 `jschardet`）→ 太重
- 需要额外依赖
- 检测不一定 100% 准确
- 在前端做这件事本身就很勉强

### 最终方案（方案 A：简化）
**策略**：不自动注入 `.cpg`，只做警告提示，由用户自行修复数据源。

**代码修改**：
1. **`assets/geojsonloader.js`**（`handleFolderUpload`，文件夹上传）：
   - `companionExts` 扩展为 8 个：`.dbf` `.shx` `.prj` `.cpg` `.xml` `.sbn` `.sbx`
   - 区分三级：必要（`.dbf`→报错）、重要（`.shx`/`.prj`/`.cpg`→提示）、可选（`.xml`/`.sbn`/`.sbx`→不警告）
   - 删除 `ensureCpgFile()` 函数
   - 解析前检查 zip 中是否有 `.cpg`，缺失则 warnings.push
2. **`index.html`**（`window.loadFileAsUserLayer`，zip 上传）：
   - 改为和文件夹上传一致：解压 zip → 每 .shp 找配套文件 → 重新打包 → `shp(newZipBuf)`
   - 用 `findEntry(zip, baseName, ext)` 按文件名（忽略路径）查找配套
   - 重要文件缺失时 `console.warn` 提示

### 补充修复：GB2312 编码自动修正
- 浏览器 `TextDecoder` 不支持 `GB2312`，只支持 `GBK`
- `shp.js` 的 `createDecoder('GB2312')` 失败 → 回退 UTF-8 → 乱码
- `handleFolderUpload` 的 zip 解析阶段（第 2200 行 `JSZip.loadAsync` 后）：
  - 找到 `.cpg` 文件 → 读取内容
  - 如果内容为 `gb2312` → 自动替换为 `GBK` + 警告用户
  - 如果无 `.cpg` → 警告用户手动创建

**警告文案**：
```
xxx.shp 缺少 .cpg 文件，如果属性表中文乱码，
请用记事本创建同名 .cpg 文件（内容为 UTF-8 或 GBK），
与 .shp 放在同一目录后重新上传。

xxx.shp 的 .cpg 文件内容为 GB2312（浏览器不支持此编码），
已自动修正为 GBK。如仍有问题，请手动将 .cpg 内容改为 GBK。
```

### 经验教训
1. **前端不适合做编码检测**：编码问题本质上属于数据问题，应该在数据源修复
2. **`.cpg` 文件创建要点**：
   - 用 VS Code 或 Notepad++ 创建（无 BOM）
   - 内容只能是 `UTF-8` 或 `GBK`（浏览器支持的名称）
   - 不能用 Windows 记事本（会加 BOM）
3. **`shp.js` 编码映射**：`createDecoder` 中有 `windows-xxxxx` 的映射逻辑，但 `GB2312` 不在映射范围内
4. **KML/KMZ/GeoJSON 无此问题**：这些格式有标准编码声明机制（XML 声明 / UTF-8 强制）
