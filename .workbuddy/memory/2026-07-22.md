## 从 ArcGIS MapServer 接入 GeoJSON 图层的方法（可复用）
- 数据源示例：UNEP-WCMC Global_Islands `https://data-gis.unep-wcmc.org/server/rest/services/Global_Islands/MapServer`（4 个多边形图层：VerySmall 7.7万 / Small 26.9万 / Big 2.2万 / Continents 6，共约 37 万要素）
- 老版本 ArcGIS Server **不支持 `f=geojson`**（返回 400），改用 `f=json`（esri 原生）+ `outSR=4326` 直接拿经纬度坐标；`maxRecordCount=1000`，用 `resultOffset` 分页。
- esri `geometry.rings`（[x,y]=[lon,lat]）转 GeoJSON：`ringArea>=0` 判外环起新部件、负判孔洞；单部件→Polygon、多部件→MultiPolygon。注意跳过 `<4` 顶点的退化环。
- 体量警告：详细多边形极其占空间——VerySmall 4 万要素未压缩已 104MB；Small(26.9万) 原始预计 ~700MB、gz 数十~上百 MB。**全量矢量多边形在 Leaflet 默认 SVG 渲染下必崩**（地图未开 `preferCanvas`）。本项目的多边形走矢量（Canvas 仅点用）。
- 落地方式（贴合现有架构，无需 COS）：生成 `.geojson` → gzip 成 `.geojson.gz` 丢进 `assets/geojson/`（已 git tracked）→ 在 `assets/geo-config.js` 的 `window.geoJsonGroups` 加条目。**新增分组必须放在数组末尾**，否则 `globalLayerIndex` 重排会打乱用户 localStorage 已保存的图层勾选状态。
- 新图层默认不勾选（面板 change 事件才 `loadGeoJSONLayer`），不会打开网页就自动全量加载。
- 构建脚本要点：37 万要素**不能**全攒内存（Node 会 OOM，4 万就崩），必须边拉边 `createWriteStream` 流式写盘 + `zlib.createGzip` 管道压缩，写完 `unlinkSync` 删原始。临时脚本 `_tmp_build_islands.js` 已验证可行（流式版）。
- 临时脚本/日志：`.tmp_build_islands.js`、`.tmp_build_islands.log`（跑完应删除，勿提交 `.tmp_*`）。

## esri-leaflet 作为矢量加载方案（用户 2026-07-22 确认可行）
- `L.esri.featureLayer({url:'.../MapServer/<id>'})` 可直接把 ArcGIS MapServer 子图层当 Leaflet 矢量层加载，**自动请求 outSR=4326、无需手动重投影**；支持 `.style()` / `.bindPopup()` / `load`/`error` 事件。用户实测可行（demo 用 /0 超小岛）。
- 本质是矢量（非瓦片）：按**当前视口 bbox** 做 query，moveend 重新请求。→ 高缩放只画视口内少数岛屿流畅；**世界缩放一次性拉全量 → 受 server maxRecordCount 传输上限限制只画前 N 条（不完整）或卡死 SVG**。
- 新增 CDN 依赖（esri-leaflet@3.x，需 Leaflet 1.9+）；debug 版(`esri-leaflet-debug.js`)仅开发用，生产用 `esri-leaflet.js`。
- 子图层 ID：/0=VerySmall(7.7万)、/1=Small(26.9万)、/2=Big(2.2万)、/3=Continents(6)。demo 用 /0 最小岛最吃力，示范建议用大岛/大陆。
- 组合建议：featureLayer 适合「大岛+大陆(小量) 或 高缩放下看局部小岛」；**37 万全量流畅的正解仍是零依赖 `L.gridLayer+export` 栅格瓦片**；要性能+交互可加 `minZoom` 控制 featureLayer 不进世界缩放。

## 补充（同日晚续验证 Global_Islands）
- **f=geojson / f=pbf 都不可靠**：二者与 f=json 走同一条 `query` 管道（限流时同样返回 `400 Failed to execute query`）。PBF 是 Esri 二进制要素格式（Protobuf 编码的要素集合，**不是** Mapbox 矢量瓦片），成功时返回 `application/octet-stream` 二进制要素、需专有解码、浏览器无原生支持；即便可用，仍是「一次拉全部要素」，不解决 37 万渲染问题。geojson 偶尔 000 超时、pbf 需解码，均不如 f=json 稳。→ **Leaflet 项目里 PBF 是最差选择**。

  - 面板生成、勾选、全选/组选、搜索结果点击、页面刷新恢复勾选：全部按 `checkbox.dataset.layerType==="arcgis"` 分流到 `loadArcgisVectorLayer`。
- **搜索/下载零改动**：因 `buildSearchIndex` 已填充 `searchIndexMap[checkboxId]` 与 `featureCache[checkboxId]`，现有 `runSearch` 与 `exportLayerGeoJson` 直接对 esri 图层生效（结果按 geometry 坐标定位）。
- ⚠️ 风险：小岛(26.9万)/超小岛(7.7万) 全量快照 ≈ 700MB/100MB 落 IDB + 占内存，首次极慢、可能令标签页卡顿；`setCache` 配额失败会静默降级（仅内存索引，仍可用）。后续若卡，可改：① 轻量索引（几何简化为代表点，仅用于定位）+ 仍存全量 IDB；② 或切服务端 `featureLayer.query().where().run()` 搜索（覆盖全量、不落本地）。
- 调试：浏览器开 F12 看 `[arcgis]` 前缀 console 日志；esri 视口查询本身已在用户浏览器验证可用（`L.esri.featureLayer`）。
- **VectorTileServer 存在但需 Token**：`/Global_Islands/VectorTileServer?f=pjson` 返回 `code 499 Token Required` → 真·矢量瓦片(MVT)被鉴权限流，匿名不可用。所以本站唯一开放的「瓦片」只有 export 栅格出图。
- **WMS 不可用**：MapServer capabilities = `Map,Query,Data`，无 WMS；`/WMSServer` 路径返回 400。不能直接 `L.tileLayer.wms`。
- **export 出图可用 ✅**：`/MapServer/export?bbox=...&bboxSR=3857&imageSR=3857&size=256,256&dpi=96&format=png24&transparent=true&f=image` 实测 200 image/png（23KB）。瓦片叠加路线根基。
- **瓦片叠加实现（无新依赖）**：`L.GridLayer({createTile})`，每 z/x/y 算 EPSG:3857 bbox（worldSize=2*20037508.342789244，res=worldSize/2^z，y 向下），`<img>.src` 指向 export URL。`singleFusedMapCache:false` 且无 tileInfo → esri-leaflet 的 TiledMapLayer 用不了；可用 `L.esri.DynamicMapLayer`（按视口出整图，更简单但加依赖）。本项目自包含、已大量用 WMS，最干净是 GridLayer+export 自渲染。
- 结论：37 万岛屿全量矢量不现实；**瓦片（export 服务端渲染）最优路线**，全量也流畅。GeoJSON 仅适合大岛+大陆(2.2万)子集。geo-config 里已加的 4 条 GlobalIslands_*.geojson.gz 配置是 GeoJSON 路线占位，文件未生成（点选会 404），若改走瓦片应换成 ArcGIS-overlay 配置。

## 收尾补丁：dynamicMapLayer 崩溃 `layers.join is not a function`
- **现象**：勾选海岛 / 拖动 / 缩放 → 控制台刷 `DynamicMapLayer.js _buildExportParams: this.options.layers.join is not a function`。
- **根因（已查本地 esri-leaflet.js 源码确认）**：`dynamicMapLayer._buildExportParams` 里 `if(this.options.layers){ if(0===this.options.layers.length)return; e.layers=\`show:${this.options.layers.join(",")}\` }` —— 它要求 `layers` 是**数组**（自己拼 `show:0,1`），并先查 `.length` 再调 `.join`。我之前写成字符串 `"show:" + layerId`，字符串有 `.length` 走进入分支、但**没有 `.join` 方法** → 抛错。
- **修法（index.html `mkIslandOverlay`）**：`layers: "show:" + layerId` → `layers: [layerId]`（layerId 为数字 0/1/2/3）。一处改动即可。
- 注：GEBCO 等 `L.tileLayer.wms` 的 `layers:"GEBCO_LATEST"` 是 WMS 字符串参数（正确），与本次无关、勿改。
- **为什么用户贴的 featureLayer demo「更流畅」**：① 那个 demo 本来就没崩、能正常渲染；② `featureLayer` 是**矢量、按视口 bbox 取数**，低缩放时受 server `maxRecordCount=1000` 截断、只画前 1000 个岛的**子集** → 要素少自然快，代价是低缩放下图不完整。修好崩溃后 `dynamicMapLayer` 同样流畅（每视口一张服务端 PNG），但它**是栅格图、无逐要素点击/弹窗**——要可点的岛需回退 featureLayer（又回到低缩放不全的坑）。

## 海岛定案：改为 featureLayer 矢量视口加载（2026-07-22 最终版）
- **用户反馈**：`dynamicMapLayer` 服务端渲染整图"基本没用，太慢了"，要求改成和 demo 一样的 `L.esri.featureLayer` 方式。
- **改动（仅 `index.html`）**：
  - 在 leaflet.js 后添加 `assets/esri-leaflet.js` 引用。
  - 新增 `createIslandLayer(layerId, displayName)` 工厂函数，创建 `L.esri.featureLayer`，默认蓝色样式（`#3388ff`，`weight:1,opacity:0.8,fillOpacity:0.25`），绑定弹窗优先用 `window.GeoUtils.buildPopupContent`（项目的统一弹窗风格），兜底用内联属性表。
  - 4 条 URL：`/0`=超小岛、`/1`=小岛、`/2`=大岛、`/3`=大陆，命名为 `ArcGIS全球超小海岛/小海岛/大海岛/大陆`（用户要求的命名规范）。
  - 放入 `moreOverlays` → **仅在"更多底图"开启后出现**在图层控件的多选覆盖层中。
- **图层记忆**：现有 `dupal_overlays` 系统已按**图层名（name）**存储——`overlayadd`/`overlayremove` 用 `e.name`，`allOverlaysLookup[name]` 恢复时匹配。岛名均唯一，无需序号兜底。用户要求「靠图层的 name，重复 name 用序号兜底」——现有机制天然满足。
- **搜索**：岛上要素可被 `runSearch` 通过名字查到吗？—— featureLayer（不是 geojsonloader 管理的图层）**目前不会被 runSearch 覆盖**。后续若需岛名搜索，需在 `runSearch` 第三阶段加服务端 where 查询（类似之前废弃的 `islandOverlaySearch` 路线）。
- **颜色后续**：用户说「颜色暂时这样默认，后续考虑设置」。届时需找到 featureLayer 实例并调 `.setStyle()`，或通过 `moreOverlays` 遍历。
- 语法校验：`node -e "new Function(...)"` 所有 5 个 `<script>` 块均通过。esri-leaflet.js（66KB，含 featureLayer）已确认可用。

## geojsonloader.js 图层记忆改为 name 稳定 ID
- **问题**：原 `checkboxId = "layer_" + globalLayerIndex++`（是遍历序号），`persistLayerCheckState` 存 `dupal_layer_<序号>` → 中间插入/移动图层后序号全变 → 旧记忆对应错误图层。
- **修法**：
  - `generateLayerItems` 内新增 `makeLayerStableId(layerName, fallback)`：用 `layerName`（兜底 file/url）小写 + sanitize + 去重后缀（冲突则 `_2/_3`）；`_seenLayerIds = {}` 每轮面板生成重置。
  - 替换 line 2737：`checkboxId = "layer_" + stableName`（不再用 `globalLayerIndex++`）。
  - `globalLayerIndex` 保留仅用于 `getFixedColor(idx)` 颜色种子，不影响存储。
- **效果**：`checkboxId` 稳定（如 `layer_火山_volcanos`、`layer_国家行政区_countries`），插入/移动图层不影响已有记忆。旧 `dupal_layer_layer_N` 键成为孤儿，用户需重新勾选一次。
